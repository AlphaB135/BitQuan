Key Vulnerabilities Fixed

Critical Severity

  • CHAIN-NEW-001: Wallet cache TOCTOU race condition
    Complete architectural refactor to single RwLock<CacheState>
  • CHAIN-NEW-005: CORS allow_any_origin() exposure
    Replaced with whitelist-based origin validation
  • NEW-001/002: Eclipse attack prevention
    Enforced subnet diversity (max 8 peers per /24 IPv4 or /48 IPv6)

High Severity

  • CHAIN-NEW-002: Faucet rate limiter TOCTOU
    Replaced with atomic Entry API (dashmap)
  • CHAIN-NEW-011: Atomic memory ordering
    Changed 19 occurrences from Ordering::Relaxed to Ordering::SeqCst
  • CHAIN-NEW-012: Integer overflow in cache accounting
    Used saturating arithmetic instead of i64 casting

Medium Severity

  • CHAIN-NEW-003: Script op_count reset regression
    Removed incorrect self.op_count = 0 from execute() method
  • Various: Memory exhaustion protections
    Added capacity checks for headers_queue (2000) and pending_blocks (500)

Attack Resistance Verification

Resource Exhaustion

✓ DEFENDED

CVE-2025-54604 style attack with 10MB payloads rejected at OS level. Node memory remained stable at 22.9MB.

Integer Overflow

✓ DEFENDED

CVE-2026-34219 style attack with extreme values (i64::MAX, u64::MAX). All handled gracefully with saturating arithmetic.

Eclipse Attack

✓ DEFENDED

Subnet diversity enforced: max 8 peers per /24 (IPv4) or /48 (IPv6). Anchor nodes whitelisted.

Rate Limit Bypass

✓ DEFENDED

50 concurrent requests: 48 blocked with "Rate limit exceeded". Only 2 processed (failed to mine).

Protocol Downgrade

✓ DEFENDED

JSON-RPC 1.0 and missing jsonrpc field rejected. Strict JSON-RPC 2.0 enforcement.

Serialization Bomb

✓ DEFENDED

1000-level nested JSON rejected by parser. serde_json has built-in recursion limits (128 levels).

Timing Attack

⚠ NEUTRAL

Valid vs invalid request times: 11ms vs 11ms (0ms delta). Not critical for blockchain. Network latency masks micro-timing.
