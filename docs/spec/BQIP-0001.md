# BQIP-0001: Transaction and Block Data Structures

- Author: BitQuan Core <dev@bitquan.org>
- Status: Draft
- Type: Standards Track
- Created: 2025-10-25

## Abstract
Defines the canonical transaction and block data structures for BitQuan, including versioning and serialization rules, with PQC-first assumptions.

## Motivation
Provide a stable, reviewable baseline for interoperability and long-term security, enabling independent implementations and test vectors.

## Specification
The normative definitions are maintained in the following specification document:
- transactions_blocks.md (this directory)

See: [transactions_blocks.md](./transactions_blocks.md)

## Rationale
- PQC signatures (e.g., Dilithium) are first-class to target a 50+ year security horizon.
- 64-bit nonce and Bitcoin-compatible difficulty field ease miner implementation and analysis.
- Compact variable-length integers minimize overhead while keeping wire format simple.

## Backwards Compatibility
Initial definition; compatibility considerations apply only to future revisions via version fields and BQIP assignments.

## Security Considerations
- Signature scheme selection and parameterization must follow current cryptanalytic guidance.
- Aggregate signature hints are reserved; activation must be gated by dedicated BQIPs and audits.
- Transaction and block weight rules must prevent abuse from large PQC artifacts.
