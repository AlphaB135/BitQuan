# BQIP-0004: Witness Data and L2 Integration (with Migration Plan)

- Author: BitQuan Core <dev@bitquan.org>
- Status: Draft
- Type: Standards Track
- Created: 2025-10-25

## Abstract
Introduces segregated witness data and L2 commitment anchors to BitQuan transactions/blocks. Defines versioning and migration so existing Transaction structures evolve safely.

## Motivation
Reduce on-chain verification cost (batch/streamed witness), enable L2 rollups/bridges to commit succinctly on L1, and preserve long-term upgradability without breaking nodes.

## Specification
### 1. Transaction Versioning and Flags
- Bump Transaction.version from v1 → v2 when witness is activated on the network (activation TBA).
- Add a `flags` byte (reserved in v1, active in v2). `flags & 0x01 != 0` indicates presence of witness data.
- Serialization order (v2): header fields → inputs → outputs → [optional witness section] → algo/signatures.

### 2. Witness Section (Segregated)
- `witnesses: Vec<Witness>` present only when `flags & 0x01 != 0`.
- `Witness` structure (TBD exact fields): stack-oriented items supporting PQC signatures, aux proofs, and future multisig/script extensions.
- Witness bytes are excluded from legacy digest calculation but included in a separate `witness_root` merkle (see §4).

### 3. Weighting and Fees
- Block/tx weight includes a discounted factor for witness bytes: `weight = base_bytes + α * pqc_items + β * witness_bytes` (α, β TBD; initial α=384, β in [0.25..1.0]).
- Mempool enforces per-tx and per-block weight limits; fee rate computed over weight, not raw size.

### 4. Block Header Extensions
- Add optional `witness_root: [u8;32]` in header v2 (keep v1 header for pre-activation). For mixed networks, keep header versioning.
- `pqc_agg_hint` remains reserved and can commit to batch/aggregate schemes that verify witness efficiently.

### 5. L2 Anchoring
- Define `OP_RETURN`-like commitment output type `OP_L2COMMIT <tag> <digest>` (exact opcode/encoding TBD via separate BQIP).
- Standard tags for: rollup state root, message queue root, and bridge checkpoints.
- Validation: nodes do not interpret L2 state, only commit shape/size limits.

### 6. Node/Network Behaviour
- Pre-activation nodes (v1) accept only v1 transactions. Post-activation nodes accept v1 and v2; miners SHOULD prefer v2 for scalability.
- P2P: new inventory/type IDs for witness-carrying tx/blocks to allow relay policy differentiation.

## Migration Plan
1. Author test vectors and finalize `Witness` layout and `witness_root` computation.
2. Implement bitquan-types v2 (Transaction v2, header v2) in a feature-gated branch.
3. Ship nodes that are v2-aware but keep v1 default; run on testnet with activation height/time.
4. Activate via BQIP-defined mechanism; after activation, mempool policy prefers v2 and discounts witness fees.
5. Deprecate v1 once usage falls below threshold; remove behind a later BQIP.

## Backwards Compatibility
- Strictly additive with version bumps; v1 tx remain valid post-activation. Legacy digest excludes witness; new digest covers witness via `witness_root`.

## Security Considerations
- DoS: cap witness items count/size; bound β; enforce per-script step limits.
- Malleability: signatures reside in witness; transaction id (txid) excludes witness, while wtxid includes it to bind signatures.
- L2 commitments: size-limited, tagged, and non-interpreted by L1 to avoid consensus ambiguity.

## Test Plan
- Unit tests for serialization, txid/wtxid, and witness merkle.
- Mempool policy tests for weight/fee handling.
- Testnet activation rehearsal with mixed v1/v2 traffic and L2 anchor stress.
