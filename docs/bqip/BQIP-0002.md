# BQIP-0002: Block Weight and Fee Market

```
BQIP: 0002
Title: Block Weight System and Fee Market Policy
Author: BitQuan Maintainers
Status: Draft
Type: Standards Track
Created: 2025-10-26
```

## Abstract

This BQIP defines the block weight system to account for post-quantum signature
sizes and establishes mempool ordering policy based on fee-per-weight.

## Motivation

Post-quantum signatures are 40-50x larger than ECDSA signatures. Without weight
adjustment, PQC transactions would consume unfair block space and distort fee
markets. This proposal ensures fair capacity allocation and economically
rational fee dynamics.

## Specification

### Constants

```rust
const SIGNATURE_WEIGHT: usize = 384;        // Weight units per signature
const MAX_BLOCK_WEIGHT: usize = 4_000_000;  // Maximum block weight
const WITNESS_SCALE_FACTOR: usize = 4;      // Segwit-style scaling
```

### Weight Formula

```
tx_weight = (base_size * WITNESS_SCALE_FACTOR) + (signature_count * SIGNATURE_WEIGHT)

where:
  base_size = serialized size without witness data (bytes)
  signature_count = total signatures in transaction
```

### Block Weight Limit

```
block_weight = sum(tx_weight for tx in block.transactions)

Validation: block_weight <= MAX_BLOCK_WEIGHT
```

## Mempool Policy

### Fee-Per-Weight Ordering

Transactions ordered by priority:

```
priority = transaction_fee / tx_weight
```

Unit: qbits per weight unit (qbits/WU)

### Minimum Fee Rate

Default: 1 qbit/WU

```
min_fee = tx_weight * 1 qbit/WU
```

Configurable by node operators.

### Transaction Acceptance

Accept transaction if:
1. fee_rate >= min_fee_rate
2. tx_weight <= MAX_BLOCK_WEIGHT
3. mempool size < max_mempool_size (300 MB default)

### Transaction Eviction

When mempool full:
1. Remove transactions with lowest fee_rate
2. Maintain min_fee_rate floor
3. Never evict txs with fee_rate >= 10 qbits/WU

### Replace-By-Fee (RBF)

Allow replacement if:
1. new_fee >= old_fee + (new_weight * min_fee_rate)
2. new_weight <= old_weight * 2
3. BIP125 signaling (sequence < 0xfffffffe)

## Block Template Construction

### Algorithm

```python
def build_block_template(mempool, max_weight):
    # Sort by fee per weight (descending)
    sorted_txs = sorted(mempool,
                       key=lambda tx: tx.fee / tx.weight,
                       reverse=True)

    selected = []
    total_weight = coinbase_weight
    total_fee = 0

    for tx in sorted_txs:
        if total_weight + tx.weight <= max_weight:
            selected.append(tx)
            total_weight += tx.weight
            total_fee += tx.fee

    return selected, total_fee
```

### Ancestor Fee Rate

Consider ancestor transactions in mempool:

```python
def effective_fee_rate(tx, mempool):
    ancestors = get_ancestors(tx, mempool)
    total_fee = sum(t.fee for t in ancestors) + tx.fee
    total_weight = sum(t.weight for t in ancestors) + tx.weight
    return total_fee / total_weight
```

## Rationale

### SIGNATURE_WEIGHT = 384

Dilithium3 signatures: ~3,000 bytes
With witness discount (4x): 3,000 / 4 = 750 WU

We use 384 WU (50% discount) to:
- Encourage PQC adoption
- Maintain compatibility with Bitcoin's weight model
- Ensure fair block space allocation

### MAX_BLOCK_WEIGHT = 4,000,000

Matches Bitcoin's limit for:
- Ecosystem familiarity
- Well-tested capacity
- Network bandwidth compatibility

Estimated capacity:
- Average tx: ~1,500 WU
- Transactions per block: ~2,600
- Transactions per day: ~374,000

## Implementation

### Consensus Rules

```rust
fn validate_block_weight(block: &Block) -> Result<(), Error> {
    let weight = block.transactions.iter()
        .map(|tx| calculate_tx_weight(tx))
        .sum();

    if weight > MAX_BLOCK_WEIGHT {
        return Err(Error::ExcessiveBlockWeight);
    }

    Ok(())
}
```

### Mempool Ordering

```rust
struct MempoolEntry {
    tx: Transaction,
    fee: u64,
    weight: usize,
    fee_rate: f64,
    time_added: Instant,
}

impl Ord for MempoolEntry {
    fn cmp(&self, other: &Self) -> Ordering {
        self.fee_rate.partial_cmp(&other.fee_rate)
            .unwrap_or(Ordering::Equal)
            .reverse()
    }
}
```

### Property Tests

```rust
#[quickcheck]
fn block_weight_deterministic(block: Block) -> bool {
    let w1 = calculate_block_weight(&block);
    let w2 = calculate_block_weight(&block);
    w1 == w2
}

#[quickcheck]
fn tx_weight_monotonic(tx: Transaction) -> bool {
    let base_weight = calculate_tx_weight(&tx);

    let mut tx_more_sigs = tx.clone();
    tx_more_sigs.witnesses.push(Witness::default());

    calculate_tx_weight(&tx_more_sigs) > base_weight
}
```

## Backwards Compatibility

Active from genesis. No backwards compatibility concerns.

## Security Considerations

### DoS Protection

Weight limit prevents:
- Excessive signature verification (max ~10,000 signatures per block)
- Memory exhaustion (max 4 MB block)
- CPU exhaustion (bounded verification time)

### Fee Market Stability

Fee-per-weight ensures:
- Fair competition for block space
- Predictable transaction costs
- Economic incentive alignment
