# BQIP-0003: Difficulty Retarget (ASERT)

```
BQIP: 0003
Title: Absolute Scheduled Exponential Rising Targets (ASERT)
Author: BitQuan Maintainers  
Status: Draft
Type: Standards Track
Created: 2025-10-26
```

## Abstract

This BQIP defines the difficulty adjustment algorithm using ASERT (Absolute
Scheduled Exponential Rising Targets) for per-block retargeting with 1-day
half-life.

## Motivation

Bitcoin's 2016-block difficulty adjustment creates:
- Hash rate volatility between adjustments
- Potential for gaming around boundaries
- Slow response to hash rate changes

ASERT provides:
- Smooth per-block adjustments
- Fast response to hash rate changes (1-day half-life)
- Resistance to timestamp manipulation
- Mathematical elegance

## Specification

### Constants

```rust
const TARGET_BLOCK_TIME: i64 = 600;        // 10 minutes (seconds)
const HALF_LIFE: i64 = 86400;              // 1 day (seconds)
const MIN_DIFFICULTY: u32 = 0x207fffff;    // Minimum target (testnet-like)
```

### ASERT Formula

```
next_target = anchor_target * 2^((time_delta - height_delta * 600) / 86400)

where:
  anchor_target = target from anchor block
  time_delta = current_time - anchor_time
  height_delta = current_height - anchor_height
  600 = TARGET_BLOCK_TIME
  86400 = HALF_LIFE
```

### Anchor Block

Initial anchor (genesis):
```
anchor_height = 0
anchor_time = 1729944000 (Oct 26, 2025 12:00:00 UTC)
anchor_target = 0x207fffff (very low difficulty)
```

### Target Calculation

```rust
fn calculate_next_target(
    current_height: u64,
    current_time: u32,
    anchor_height: u64,
    anchor_time: u32,
    anchor_target: u32,
) -> u32 {
    let height_delta = (current_height - anchor_height) as i64;
    let time_delta = (current_time - anchor_time) as i64;
    
    // Expected time for this many blocks
    let expected_time = height_delta * TARGET_BLOCK_TIME;
    
    // Actual vs expected deviation
    let time_diff = time_delta - expected_time;
    
    // Exponential adjustment
    let exponent = time_diff as f64 / HALF_LIFE as f64;
    let multiplier = 2_f64.powf(exponent);
    
    // New target
    let anchor_target_expanded = expand_compact(anchor_target);
    let new_target = anchor_target_expanded * multiplier;
    
    // Clamp to min difficulty
    let min_target = expand_compact(MIN_DIFFICULTY);
    let clamped = new_target.min(min_target);
    
    compact_target(clamped)
}
```

### Compact Target Format

```rust
fn expand_compact(compact: u32) -> f64 {
    let exponent = (compact >> 24) as i32;
    let mantissa = compact & 0x00ffffff;
    mantissa as f64 * 2_f64.powi(8 * (exponent - 3))
}

fn compact_target(target: f64) -> u32 {
    if target == 0.0 {
        return 0;
    }
    
    let exponent = (target.log2() / 8.0).floor() as i32 + 3;
    let mantissa = (target / 2_f64.powi(8 * (exponent - 3))) as u32;
    
    ((exponent as u32) << 24) | (mantissa & 0x00ffffff)
}
```

## Validation Rules

1. Block timestamp must be > median of last 11 blocks (MTP)
2. Block timestamp must be < current time + 2 hours
3. Block bits must match calculated target
4. Block hash must be <= target

## Examples

### Example 1: On-Time Blocks

```
Anchor: height=0, time=1729944000, target=0x207fffff
Current: height=144, time=1729944000+86400

time_delta = 86400 seconds
height_delta = 144 blocks
expected_time = 144 * 600 = 86400 seconds
time_diff = 0 (exactly on time)

exponent = 0 / 86400 = 0
multiplier = 2^0 = 1.0
next_target = anchor_target * 1.0 = 0x207fffff (unchanged)
```

### Example 2: Blocks 2x Too Fast

```
Anchor: height=0, time=1729944000, target=0x207fffff
Current: height=144, time=1729944000+43200

time_delta = 43200 seconds (12 hours)
expected_time = 86400 seconds (24 hours)
time_diff = 43200 - 86400 = -43200

exponent = -43200 / 86400 = -0.5
multiplier = 2^(-0.5) = 0.707
next_target = anchor_target * 0.707 (difficulty increases)
```

### Example 3: Blocks 2x Too Slow

```
Anchor: height=0, time=1729944000, target=0x207fffff
Current: height=144, time=1729944000+172800

time_delta = 172800 seconds (48 hours)
expected_time = 86400 seconds (24 hours)
time_diff = 172800 - 86400 = 86400

exponent = 86400 / 86400 = 1.0
multiplier = 2^1.0 = 2.0
next_target = anchor_target * 2.0 (difficulty decreases)
```

## Implementation

### Consensus Code

```rust
pub fn next_difficulty_target(
    current_header: &BlockHeader,
    parent: &BlockHeader,
    anchor_height: u64,
    anchor_time: u32,
    anchor_bits: u32,
) -> Result<u32, Error> {
    // Validate timestamp
    if current_header.time <= parent.time {
        return Err(Error::InvalidTimestamp);
    }
    
    // Calculate using ASERT
    let target = calculate_next_target(
        current_header.height,
        current_header.time,
        anchor_height,
        anchor_time,
        anchor_bits,
    );
    
    Ok(target)
}
```

## Testing

### Property Tests

```rust
#[quickcheck]
fn asert_monotonic_time(height: u64) -> bool {
    let state = DifficultyState::genesis();
    
    let time1 = state.anchor_time + 100000;
    let target1 = calculate_next_target(
        height, time1,
        state.anchor_height, state.anchor_time, state.anchor_bits
    );
    
    let time2 = time1 + 10000;
    let target2 = calculate_next_target(
        height, time2,
        state.anchor_height, state.anchor_time, state.anchor_bits
    );
    
    // Later time = higher target (easier difficulty)
    target2 >= target1
}

#[test]
fn asert_half_life() {
    let state = DifficultyState::genesis();
    
    // After half-life with no blocks: target doubles
    let target = calculate_next_target(
        0, state.anchor_time + 86400,
        state.anchor_height, state.anchor_time, state.anchor_bits
    );
    
    let expected = state.anchor_bits * 2;
    assert_approx_eq!(target, expected, 0.01);
}
```

## Rationale

### 1-Day Half-Life

Chosen for:
- Fast response to hash rate changes (Bitcoin: 2 weeks)
- Stability against short-term variance
- Balance between responsiveness and stability

### Per-Block Adjustment

Benefits:
- No incentive to time blocks around boundaries
- Smooth difficulty changes
- Immediate response to sustained hash rate changes

### Exponential Formula

Properties:
- Symmetric response to fast/slow blocks
- Continuous and smooth
- No oscillation or feedback loops

## Security Considerations

### Timestamp Manipulation

Miners can manipulate timestamps by ±2 hours. With 1-day half-life:
```
max_manipulation = 2 hours = 7200 seconds
exponent = 7200 / 86400 = 0.083
multiplier = 2^0.083 = 1.059 (5.9% difficulty change)
```

Limited impact prevents gaming.

### Future Timestamp Limitation

```
if block.time > current_time + 7200 {
    return Err(Error::TimestampTooFar);
}
```

### Median Time Past (MTP)

```
if block.time <= median_time_past(last_11_blocks) {
    return Err(Error::TimestampTooEarly);
}
```

Prevents backwards time manipulation.

## Activation

Active from genesis block. No activation required.
