## CRITICAL (8)

### GHOST Protocol

1. **Main block PoW never verified in validate_block** (lib.rs:674-721)
   - validate_block_header checks bits range and merkle root but NOT hash meets target
   - Only uncle headers get PoW check; main block header does not
   - Attacker can broadcast blocks without proof-of-work

2. **No same-block duplicate uncle detection** (lib.rs:589-608)
   - Double-inclusion check only against past_uncle_hashes from previous blocks
   - Same uncle header can appear twice in block.uncles for double nephew reward

3. **Uncle height defaults to height-1 when not found** (worker.rs:740-748)
   - Height scan range is only 10 blocks; if uncle not found, defaults to height-1
   - Uncle from depth 8+ gets rewarded as depth 1

### ASERT / Difficulty

4. **compact_to_target maps all valid difficulty to u64::MAX** (difficulty.rs:27-29)
   - Any compact bits with exponent >= 11 returns u64::MAX
   - All network-valid bits (exponent 28-32) collapse to single value
   - ASERT operates on degenerate input; fundamentally broken for production

5. **fp_pow2 lookup table values incorrect (up to 9.35% error)** (asert.rs:126-132)
   - Precomputed 2^x values have systematic errors
   - Different implementations would produce different targets -> consensus split

6. **Ethash PoW is a no-op placeholder** (pow.rs:365-376, 439)
   - Cache is 1MB of zeros; nonce always H64::default()
   - Any block passes Ethash "verification"

7. **Feature-gated PoW fallbacks create consensus split risk** (pow.rs:311-322, 487-499)
   - RandomX disabled -> SHA-256 fallback; Ethash disabled -> Keccak-256 fallback
   - Nodes with different feature flags compute different hashes

### P2P / Chain State

8. **append_block has no validation** (chainstate.rs:105-126)
   - Block parameter ignored (_block); height/tip_hash from caller arguments
   - Any caller can set chain to arbitrary state

## Priority Remediation Order

### Phase 1: Critical Security Fixes
1. Add check_header_pow to validate_block_header (C-1)
2. Fix compact_to_target to use U256 (C-4)
3. Fix fp_pow2 lookup table values (C-5)
4. Remove/disable Ethash until properly implemented (C-6)
5. Remove PoW fallback implementations (C-7)
6. Add validation to append_block (C-8)
7. Add duplicate uncle check within current block (C-2)
8. Reject blocks where uncle height not found (C-3)

### Phase 2: High Priority
9. Add ancestry check for uncles
10. Validate uncle PoW against expected difficulty
11. Add height_delta > 0 validation in ASERT
12. Cache subtree weights incrementally
13. LRU eviction for RandomX VM cache
14. Verify peer height claims

### Phase 3: Hardening
15. Checked arithmetic for all reward calculations
16. Connection limits at TCP level
17. Hash-to-height index for IBD
18. TLS for P2P and Stratum
19. Real Stratum authentication
