# BQIP-0002: PoW Difficulty, Timestamp Policy, and Mining Protocol

- Author: BitQuan Core <dev@bitquan.org>
- Status: Draft
- Type: Standards Track
- Created: 2025-10-25

## Abstract
Defines the difficulty adjustment mechanism, timestamp validity rules, and mining protocol requirements (Stratum v2) for BitQuan PoW.

## Motivation
Provide a robust, manipulation‑resistant difficulty and time policy with modern mining protocol features to reduce centralization and improve safety.

## Specification
### 1. Consensus Parameters (TBD values)
- Target block interval: T_target = TBD_s (e.g., 60s)
- Acceptable timestamp drift: |t_block − t_wall| ≤ TBD (e.g., ±2h)
- MTP window: last N = 11 blocks (Median‑Time‑Past)
- Nonce size: 64‑bit

### 2. Difficulty Adjustment Algorithm
- Use ASERT (Absolutely Scheduled Exponentially Rising Targets) or LWMA as baseline; proposed default: ASERT with half‑life H = TBD blocks.
- Difficulty retarget is continuous per block; complexity O(1).
- Canonical formulae and fixed‑point constants to be finalized with test vectors.

### 3. Timestamp Validity and Timewarp Resistance
- A block is valid only if: timestamp ≥ MTP(prev_N) + 1s.
- Timestamp must not exceed node wall‑clock by more than Drift_max.
- Miners should prefer MTP‑aligned timestamps; nodes MUST enforce MTP and future‑drift rules.

### 4. Mining Protocol (Stratum v2 Requirements)
- Mandate Stratum v2 with: version negotiation, job negotiation, version‑rolling, and non‑custodial payout support.
- Pool MUST allow miners to construct/choose their own templates (minimize censorship risk).
- Define minimum message set and authentication; transport security via Noise or TLS (TBD).

### 5. Propagation and Orphan Rate (Informative)
- Encourage compact/graph/erasure‑coded block relay (out‑of‑scope for consensus).

## Rationale
- ASERT/LWMA mitigate oscillations and timestamp games; MTP blocks timewarp vectors.
- 64‑bit nonce broadens search space for hardware while remaining simple.
- Stratum v2 reduces pool trust and improves decentralization.

## Backwards Compatibility
Initial definition; activation via testnet parameters first. Mainnet activation subject to additional BQIP and audits.

## Security Considerations
- Parameter choices (H, drift) materially affect stability and attack costs; require simulation.
- Stratum v2 authentication and template control reduce pool‑side attacks but need careful defaults.

## Test Plan
- Simulate hashrate shocks and timestamp adversaries; compare ASERT vs LWMA.
- Network testnet with chaotic clocks; measure orphan rate and retarget tracking.
- Interop tests with at least two Stratum v2 server/client implementations.
